# CLAUDE.md

careen: a Go CLI/TUI that patches, reboots, provisions and inspects a NixOS fleet defined in a
flake. Documentation site: `docs/` + `mkdocs.yml` (Material for MkDocs), published to GitHub
Pages from `main`.

## Commands

```bash
nix develop -c go test ./...      # tests (includes internal/docscheck)
nix flake check                    # careen + tests + the docs site (mkdocs --strict)
nix build .#docs                   # the built site in ./result
scripts/docs.sh serve              # live docs preview
```

## Rules

- **Docs change with the code.** Any change to commands, flags, JSON output, inventory or flake
  fields, or behaviour updates the matching page in `docs/` in the same commit.
  `CONTRIBUTING.md` maps each kind of change to its page.
- The CLI reference (`docs/reference/cli.md`) is generated by the hidden `careen gen-docs` and
  isn't committed: improve a command's `Short`/`Long`/flag usage instead of editing it.
- `internal/docscheck` fails when a `careen.*/vN` schema or a field careen reads from the flake
  (`fleet`, `careen`, `pve`) isn't documented; fix the docs, not the test.
- Docs describe what the code does now; planned work goes in `docs/roadmap.md`.
- careen is public and deployment-neutral: no real host names, domains, subnets or keys in code,
  tests or docs (use `web1`, `db1`, `mgr`, `*.example`, `10.0.0.x`), and Go code reads only the
  flake's outputs, never `config.my.*` (`internal/docscheck` checks; see docs/development.md).
